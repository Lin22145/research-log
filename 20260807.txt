今天看了一下vibe-trading怎么从口头策略到回测报告的全过程，有点意识到它的回测报告不完美的原因，感觉是翻译口头策略的版本不一，而Alpha agent的DSL（Domain-Specific Language）方式会给LLM提供可用数据字段+ 可用操作符+ 可用因子+ 固定语法+ 参数限制+ 类型和时间约束，不能随意生成python，只能在这套词汇和语法中组合因子


1.口头策略到市场成交的完整链路
    口头策略
→ a.LLM提取策略结构
→ b.生成config.json和SignalEngine代码
→ c.原始数据计算因子
→ d.统一因子方向
→ e.每个因子做截面Z-score
→ f.因子乘权重后加总
→ g.综合分数
→ h.Top N / 连续裁剪 / 百分位映射

    其中ab由LLM实现，cdefghi由SignalEngine实现, jkl由BaseEngine实现, m由BaseEngine+绩效模块实现，o由BaseEngine+绩效模块实现


2.细节
   （1）从LLM到config.json的一些细节
        LLM会把策略分成三类：因子型策略、规则型策略、混合型策略
            
        因子型策略：计算每只股票的分数→ 横向比较→ 排名选股。 
        有以下特点：通常需要一个资产值，常使用截面排名，因子值一般是连续分数，定期调仓，常用IC、RankIC、分层收益评价，因子本身还不是交易，必须通过排名和仓位映射
            
        规则型策略：满足条件时入场→ 持有→ 满足退出条件时离场，例如：20日均线上穿60日均线买入，下穿卖出。
        不一定是比较很多股票，可以是检查某个资产是否满足明确条件，通常用收益率、Sharpe、回撤、胜率评价
            
        混合型策略： 因子负责选股，规则负责择时和风控，例如：从低估值高ROE股票中选择前10只，但只有大盘位于200日均线上方时才持有。
        有以下特点：因子解决资产选择，规则解决交易时机，风控解决持有和退出，比单纯因子或单纯规则复杂，更接近实际组合管理。
   

    
    （2）config.json
        记录用什么市场的数据，回测时间段，间隔天数，初始资金，资金配置（手续费等，market engine还能读取是否允许做空等市场规则限制），是否需要额外行情字段、基本面财务数据（funfamental_fields）,是否使用权重优化器（optimizer）优化,回测引擎模式，validation验证模块

（3）SignalEngine
    负责真正的策略计算，输入市场数据，输出每个日期的目标仓位信号。记录了因子参数，因子公式，标准化方法，因子重，选股规则，仓位映射，调仓规则
     
     完整链路如下（上面的完整链路的一部分复制下来）：
     c.原始数据计算因子
→ d.统一因子方向
→ e.每个因子做截面Z-score
→ f.因子乘权重后加总
→ g.综合分数
→ h.Top N / 连续裁剪 / 百分位映射
→ i.[-1,1]信号
     
     1.TOPN映射：选出综合分数topN的股票赋予信号值1，bottomN的股票赋予信号值-1，后续经过base engine归一化后分配资金比例
        这种方法会忽略第一名和第二名的差距
